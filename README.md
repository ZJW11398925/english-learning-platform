# 英语学习平台（拍照取词 → 跟读示范 → 造句反馈 → 间隔复现）

一个**手机浏览器可用**的英语词汇学习小站：看到实物，举起手机拍一下（或从相册选一张图），AI 认出它并给你一个要学的英文词；听一遍真人感的示范发音，跟着念一遍；然后**自己用它造一个句子**，AI 给你结构化的反馈（对不对、哪里不地道、怎么改更好）；这个词会在之后的轮次里**换一个场景再次出现**，直到你真正记住它。

核心闭环一句话：**拍照识物取词 → 跟读示范 → 自己造句 → 拿到结构化反馈 → 该词在新场景中复现。**

我们不赌"多背单词表"，我们赌的是：成年学习者愿意为一次取词举起手机拍一下，并愿意付出"造一个自己的句子"这份主动产出的成本——因为只有产出才会暴露真正的问题。

## 怎么用（五步）

1. **填 Key**：首次打开点「设置（API Key）」，粘贴你自己的 DeepSeek API Key（怎么拿见下一节）。Key 只存在**你手机的本机存储**里，永远不经过任何服务器。
2. **拍照 / 选图**：对准一个实物按快门，或从相册选一张照片。AI 认出物体，给你一个具体的英文名词（比如 `mug`）和它所在的场景（`kitchen`）。拍糊了、光线太差会被直接退回重拍，不会浪费一次识别。
3. **跟读示范**：点「听示范」听这个词的发音（手机自带的语音合成），然后**自己念一遍**——念没念对由你自己打勾确认，系统不偷听、不评判。
4. **造句**：用这个词写一个你自己的英文句子。AI 会判定它 `correct`（正确）/ `flawed`（有问题：用词、搭配或语法，并给出改写建议）/ `uncertain`（拿不准，如实告诉你它拿不准）。
5. **复现**：按记忆曲线的间隔，这个词会在之后的学习中**换个场景再次出现**——认识它的地方变了，词还在，检验的是真记住还是脸熟。

识物没认出来时不会糊弄你：要么重拍，要么退到场景词包让你手选，绝不算"学会了"。

## API Key 怎么拿

1. 打开 DeepSeek 开放平台：<https://platform.deepseek.com/>，注册并登录；
2. 在「API Keys」页创建一个新 Key（形如 `sk-…`）；
3. 复制，粘贴到本站「设置（API Key）」里保存。

费用走你自己的 DeepSeek 账户（识物一次、造句一次各是一次模型调用，通常每次不到一分钱）。**不填 Key 也能打开站点**，会有引导页告诉你怎么填，不会白屏不会崩。

## 数据与隐私

- **一切学习记录只存在你的设备上**（浏览器 localStorage：`elp.events` / `elp.words` / `elp.meta`）。没有账号系统，没有服务器数据库，我们不掌握你的任何数据。
- **图像直达模型**：你拍的照片以 base64 直连发给 `api.deepseek.com`，**不经过任何第三方服务器**（本项目根本没有服务端）。
- **API Key 同样只在本机**（`elp.apiKey`），随每次请求头直达模型服务商，不经他人之手。
- **导出**：想拿走数据时，在站点诊断页可以看到全部事件记录；开发者可在浏览器控制台把 `localStorage` 里的键导出成 JSON，用仓库里的 `node scripts/export.mjs <事件.json>` 算出学习统计（判据口径见仓库内脚本注释）。清掉浏览器数据 = 记录全没了，请自行导出备份。

## 本地开发

零构建、零运行时依赖（纯 ES Modules），本地跑起来只要一个任意静态服务器：

```bash
npx serve web          # 或 python -m http.server -d web 8000 等任意静态服务器
# 打开 http://localhost:8000 （localhost 天然是安全上下文，摄像头可用）
```

测试与证据（在仓库根）：

```bash
node --test                        # 全量测试（纯逻辑单元 + 真 HTTP 桩链路）
node scripts/mutation-probe.mjs    # 变异探针：逐个"把实现改坏"，验证测试真能抓到
node scripts/export.mjs <事件.json>   # 学习数据 → 判据统计
```

## 开发者须知：一条命令部署

站点部署是纯 git 操作（零构建）：

```bash
node scripts/deploy-pages.mjs
```

它用 `git subtree split` 把 `web/` 切到 `gh-pages` 分支根目录并推送；重复跑安全（幂等），不影响当前分支与工作树。首次开通 GitHub Pages 需在仓库设置里选 **Deploy from a branch → gh-pages / (root)**。

## 已知限制（公测前如实交代）

- **自带 Key 的 XSS 面**：Key 存在浏览器 localStorage，任何能往本站页面注入脚本的漏洞都能读到它。本站没有任何服务端、不引入第三方脚本，把注入面压到了最小，但这是"前端直连 + BYO Key"形态的固有代价。公测 Key 请控制额度、随用随删。
- **TTS 设备差异**：示范音用的是手机自带的语音合成（`speechSynthesis`），音色/语速因设备而异；个别机型上引擎可能不可用或卡住——播放有 15 秒墙钟兜底，到点自动收口，不会把界面卡死。
- **自动跟读判定的历史裁决**：早期版本用浏览器语音识别自动判定"念没念对"，在某类设备上会以 `aborted`（平台中断识别器）失败且网页侧无法修复（完整裁决记录在项目的 DMCP 设计工作区，见下节）。当前版本改为"听示范 → 自己念 → 自评打勾"，不再依赖该能力。
- 模型不是裁判：`uncertain` 是合法判定，模型拿不准时会如实说；它的判定质量上限即 DeepSeek 的上限。

## 治理

本仓库由 **DMCP 设计状态工作区**治理：设计决策（含上面的"历史裁决"）、验收判据与变更都以带签名的决策对象登记在案，仓库文档与之 digest 绑定（文档被改动即产生可检测的漂移证据）。设计 spec、实施计划与真机验证清单在 [`docs/`](docs/) 目录；工程台账（逐任务的测试与变异证据）在 `.superpowers/sdd/`。

测试数字与变异证据的当前基线：`node --test` 全绿 + `node scripts/mutation-probe.mjs` 全绿（具体数字见最近一次提交说明）。
