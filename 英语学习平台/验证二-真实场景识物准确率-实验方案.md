## 0. 这份实验真正要证伪什么

> **用户愿不愿意为了一次取词，举起手机对着身边的东西拍一下。**

真正杀死这条路径的不是"模型识别不出杯子"，而是**反复重拍**：拍一次认错、再拍一次还错，第三次用户就放下手机去翻词表了。所以本实验的核心指标不是"能不能认出来"，而是**一次成功率**——即"不重拍就能进入学习动作"的比例。

**本实验的达标与否由两条验证共同决定（均为 vertical slice 闸门）：**

| 判据 | 登记对象 | 口径 | 它回答的问题 |
|---|---|---|---|
| A：`top3 ≥ 0.85` | `VAL-…38` | 三轮取**均值** | 模型能力够不够 |
| B：`retry_rate ≤ 0.2` | `VAL-…50` | 三轮取**最差值** | **用户会不会被烦到放弃** |

**两者不能互相抵消**：A 达标而 B 超标，等于"指标好看但没人用得下去"，按不通过处理（见 §5）。B 之所以取最差轮而非均值，是因为"用户放弃"是一次坏体验就足以触发的事件，用均值裁决等于给最差的那一轮开后门。

> 判据 B 的设立本身是一条决策（`DEC-…48`）：criterion 在契约里只能挂单一比较器，因此 B 无法与 A 做与运算，只能是独立的一条验证。

## 1. 一个必须先定的口径问题（否则数据无意义）

"识别准确"在本产品里**不等于**"识别出物品的正确名词"。

用户拍一个马克杯，系统回答 `mug` 或 `cup` 或 `coffee cup`，**三种都对学习有用**；但回答 `container` 或 `ceramic` 就错了——那是上位词/材质，不是可用的场景词。

因此本实验采用 **词表可接受集判定**，而不是与单一标签字符串比对：

1. 每个测试物体**预先声明**一个"可接受词集"（1–3 个英文词，例：`mug / cup`）
2. 系统输出落在该集合内 → 计入 top-1 命中
3. 系统输出前 3 候选中有任一落在集合内 → 计入 top-3 命中
4. 输出为同义近义词但未预声明 → **不算命中**，但必须单独记录为"边界情形"，供事后校准词集（预声明不得事后追改，只能在新一轮重跑时使用）

> 这一步不做，top-3 ≥ 0.85 就是个可以随意操纵的数字。

## 2. 测试集（60 个真实物品）

**独立性要求：60 个物体不得使用任何公开评测集或训练集里的图片**，必须现场实拍。这是防数据泄漏的唯一办法。

| 类别 | 数量 | 举例 |
|---|---|---|
| 居家 | 15 | 马克杯、水壶、遥控器、抱枕、台灯、钥匙 |
| 通勤随身 | 15 | 耳机、充电宝、雨伞、卡包、口罩、交通卡 |
| 办公 | 15 | 订书机、便签、文件夹、鼠标垫、水杯、便签纸 |
| 餐饮 | 15 | 保温杯、餐具、餐盒、调料瓶、纸巾盒 |

每个物体拍 **2 种条件 × 各 3 张 ≈ 6 张**，条件在 {正常光, 弱光, 杂乱背景} 中按物体轮换分配，**保证三种条件总体分布均衡**（各约 1/3）。

拍摄约束（对应用户已登记的 applicability 维度）：
- 距离 **20–30cm**（用尺量，不凭手感）
- 至少 **2 台不同机型**拍摄，避免单一摄像头特性造成的偏差
- 不摆拍、不擦镜头、夜间弱光不补光——**要的就是难看的原始条件**

总量约 **360–540 张**。

## 3. 三轮设计（对应 required_runs = 3；判据 A 取均值，判据 B 取最差值）

| 轮次 | 内容 | 目的 |
|---|---|---|
| 第 1 轮 | 第 1 批 180 张（60 物体的正常光与弱光） | 建立基线，暴露失败模式 |
| 第 2 轮 | 第 2 批 180 张（杂乱背景为主） | 检验背景干扰下的退化幅度 |
| 第 3 轮 | 复用第 1 轮图片，**在不同时段重跑同一链路** | 分离"模型能力"与"链路/服务波动" |

**三轮取均值**（`aggregation: MEAN`）——这是 schema 登记的口径，因此**不许用"取最好一轮"来达标**。

> 已知局限：均值会掩盖某一轮严重退化。因此额外**必须**记录每轮单独数值与最差轮数值，作为结论的附带证据（不参与达标判定，但必须写进报告）。

---

## 4. 指标与记录

| 指标 | 定义 | 用途 |
|---|---|---|
| `top3_recognition_accuracy` | top-3 命中数 / 总样本数 | **判据 A（≥0.85，均值）** |
| `retry_rate` | 需重拍 ≥2 次才能取到可用词的比例 | **判据 B（≤0.2，最差轮）** |
| `top1_recognition_accuracy` | top-1 命中数 / 总样本数 | 观察一次命中体验（辅助） |
| `latency_ms_p50 / p95` | 单张识别耗时 | 超过 ~2s 用户会感到卡顿（辅助；p95 > 2000ms 时须在报告中显式标注） |
| `failure_taxonomy` | 失败归类：认错物品 / 只给上位词 / 多物体干扰 / 弱光失效 / 未检出 | 决定改法，而非只给分数 |

**每一轮必须输出失败样本清单（图片 + 预测 + 期望词集）**，供产品侧判断"这类错误在真实使用中是否致命"。

## 5. 判定（两条判据 A 与 B 的组合）

### 5.1 各自单条判定

- **判据 A（`VAL-…38`，top3 均值）**：通过 = 均值 **≥ 0.85**（附带：top1 ≥ 0.65，latency p95 ≤ 2000ms）；边缘 = 0.78–0.85；不通过 = < 0.78
- **判据 B（`VAL-…50`，retry_rate 最差轮）**：通过 = 三轮中最差一轮 **≤ 0.2**；边缘 = 0.2–0.3（仅作参考档，不构成通过）；不通过 = 最差轮 > 0.3

### 5.2 组合裁定（**唯一权威规则**）

| A | B | 结论 | 处置 |
|---|---|---|---|
| 通过 | 通过 | **通过** | 识物取词可作为首版主入口，进入 vertical slice |
| 通过 | 边缘（0.2–0.3） | **不通过** | 模型够用但体验会被重拍拖垮 → 先做多帧取词（连拍 2–3 张合并判定），再重跑 B |
| 通过 | 不通过（>0.3） | **不通过** | 同上，且必须在方案里回答"用户为什么会连拍都不愿意拍" |
| 边缘或以下 | 通过 | **不通过** | 按 5.3 的收窄三选项之一处理后再重跑 |
| 边缘或以下 | 不通过 | **不通过** | 假设被推翻：识物取词不得作为首版主入口，改为"场景词包优先、识物作为增强" |

**禁止的裁定方式**：取 A 与 B 的某种加权平均分、或用 A 的高分"抵"B 的超标。两条判据回答的是两个不同问题（模型能力 / 用户耐心），不可通约。

### 5.3 边缘档允许的收窄（仅三项，选其一）

在跑 vertical slice 之前，若 A 落在 0.78–0.85：

1. 收窄物体范围（例如首版只支持 2 个类别）
2. 改为多帧取词（连拍 2–3 张合并判定），代价是用户多等一拍
3. 词集放宽到上位词（**须评估对学习价值的影响**——上位词不是可用场景词）

任选其一后，必须在 dmcp 里改 applicability 维度并**重新登记判据**，不得在报告里口头解释。

> 判定后必须 `validation_submit` 回填**两条**验证要求：`measurements` 分别填 A、B 的数值指标，`evidence_refs` 指向测试集与失败清单版本。**只回填一条 = 此行未完成。**

## 7. 本方案已知的弱点（不要掩盖）

- **60 个物体覆盖不了长尾**。达标只说明"常见物品可用"，不说明"任何东西都能拍"。
- **判据 A 的均值口径会掩盖最差一轮**——这是 schema 登记的既定口径，本方案改不动；因此要求每轮单独数值都必须附报进报告，且**判据 B 本身已按最差轮裁决**，等于在最关键的那一项上补回了保守性。
- **`retry_rate` 是模拟重拍，不是真实重拍**。本实验里"重拍"由测试者按判定规则模拟（候选词不可用即视为需重拍），与真实用户在屏幕前的放弃阈值不完全一致。真实重拍行为要在 vertical slice 阶段用真实使用数据复核。
- **现场实拍仍可能不自觉摆拍**（拍摄者知道在为模型测数据）。缓解办法：由**非本团队成员**按清单拍，拍摄者不告知用途细节。
- **本实验只看识别，不看教学**。识别对了不等于给出的词适合学——那要等 vertical slice 阶段的真实使用才能判断。
