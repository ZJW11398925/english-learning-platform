## 0. 为什么会有这份文档（前情与一次认知修正）

本项目 09-14 的原始设计 spec 与实施计划里，**没有任何界面设计**：无屏幕清单、无信息架构、无导航形态、无版式、无视觉方向、无参考图。计划对界面的全部投入 = Task 6 里 6 行内联 `<style>`。界面是在实现里长出来的，直到 09-17 才第一次被当成一件事处理——所以"简陋"的根因不是**旧设计过时**，而是**从来没有设计过**。

更重要的是一次认知修正：设计初期把 `SCENE_FIRST` 理解成了**相机中心**的形态（把日常物品识别成词）。用户否掉了这条：

> 「软件应当引导用户自己去看，自己去想，而不是一味借助相机识别。大多数时候，用户知道他看见的东西用中文怎么说，需要拍照识别的东西很少，而且那部分现有的产品预期做不到。重要的是英语学习本身，不是各种花里胡哨的假装 nb 的功能。」

这条批评成立，理由有三：
1. **识物解决的不是用户的问题。** 用户知道自己看见的是"马克杯"，他的困难是**说不出英文**。
2. **给答案会杀死学习。** 识别 → 显示 → 点头，学习者什么都没做。学习发生在**检索**（努力调出）而非**接收**。
3. **相机中心与"生活化"是两件事。** 词应当来自**学习者自己的注意力**，不是来自某次物体检测。

由此确立本稿的第一原则。

---

## 1. 第一原则

> **相机退居次要。教学法是产品。系统引导用户自己去看、自己想；给答案只在用户已经努力之后。**

推论：
- 产品的差异化不在"识别能力"，而在**教学引擎**（提问方法 + 知识资产 + 引导纪律）。
- 任何"看起来很 nb 但用户不需要"的能力都不做（用户原话：不搞"花里胡哨的假装 nb 的功能"）。
- 识物不删除，但降级为**学习者主动求助时的一条查询路径**，而不是产品的主动脉。

## 2. 中枢：一次对话，按需换挡

形态不是"每日问卷"，也不是"聊天机器人"。是**一次围绕学习者内容的对话**，系统在对话中不断判断"此刻该做哪种教学动作"。

### 2.1 内容从哪来（解决了"替学习者规定世界"的问题）

两种来源，**用户的焦点优先**：
1. **用户带来内容**：他今天干了什么、想说什么、遇到的一个句子。系统**按他的内容**挑出教学点。
2. **系统给情境**：当没有用户内容、或需要刻意复现某个词/结构时，系统造一个情境。

设计原则：**系统不能替学习者决定他的世界**。如果每次只推系统选的词，那还是在替他规定该注意什么。

优先级规则（写死，防歧义）：
1. **用户有内容 → 只用用户的内容**，教学点从他的内容里挑。
2. **用户没有内容 → 系统才给情境**，且要**邀请他补充**自己的东西（"有没有一件跟你今天有关的事？"）。
3. 系统自选情境**不得连续两次**成为会话起点，否则形态会退回"系统规定世界"。

### 2.2 教学循环（四拍）

```
诊断 → 搭台 → 逼产出 → 给够用的帮助
```

1. **诊断**：对当前焦点，判断学习者现在能做什么（能产出？认得？完全不会？）。诊断不能靠直接问"你会吗"——要靠**让他做**。
2. **搭台**：给一个**需要用到**该词/该结构的情境或任务。台子不能太难（打击）也不能太易（无学习）。
3. **逼产出**：学习者说或写。**这一步不许跳过**——没有产出就没有诊断，也没有学习。
4. **给够用的帮助**：不是替他做完，而是给到他能往下走的**最小**帮助（一个词、一个句型、一个提示）。

### 2.3 引导纪律（写死的硬约束）

- **不替用户决定下一步**：系统给**选项**，用户选。系统可以说"我建议先…"，不能说"现在是第三关"。
- **默认姿态是配合，不是纠正**：学习者的自由产出首先被当作**表达**，不是**待批改的作业**。纠正只在特定时刻发生（见 §2.5）。这是与 `NON_GOALS` 里"应试技巧"划清界限的地方。
- **不审讯**：任何提问方式**连续使用即失效**。系统必须记录"最近用过哪些方式"，避免重复施压。
- **不制造焦虑**：不威胁、不计分、不排榜、不比较他人。

## 3. 提问方法库（本稿的核心资产）

这是"提问需有方法"的正面回答。每种方法都要回答：**什么时候用、怎么用、失败长什么样**。

### 3.1 为什么需要"库"而不是"一个流程"

要学习者用上"犹豫 / hesitate"，问"你今天怎么样"是错的。正确做法是**造一个他必须犹豫的情境**。所以：
- **方法不是外壳，方法就是教学引擎**。
- 同一个词，用不同方法教，效果不同 → 需要**方法 × 目标**的匹配表。
- 没有一种方法永远好 → 需要**换挡**。

### 3.2 方法目录（初版九种）

| 方法 | 机制 | 最适合 | 失败模式（必须防） |
|---|---|---|---|
| **角色扮演** | 给一个情境与角色，学习者必须用目标语完成交流 | 产出完整句子、时态/礼貌层级、真实语用 | 情境假、学习者出戏、系统抢话 |
| **任务驱动** | 给一个可完成的小任务（订房、投诉、问路），语言是手段 | 功能性表达、搭配 | 任务太难 → 卡死 |
| **描述与命名** | 让学习者描述眼前/回忆中的人事物 | 词汇广度、名词短语、形容词 | 变成"识物"（退回相机中心） |
| **翻译对照** | 给中文，学习者说英文；再对照地道说法 | 中式英语暴露、搭配 | 变成逐句批改 → 应试 |
| **半句接龙** | 给半句，学习者补完 | 语法结构、连接词 | 变成填空 → 机械 |
| **情境猜词** | 用英文描述，让学习者猜是哪个词 | 建立"英文释义"通路，脱离中文中介 | 描述过难 → 挫败 |
| **回忆叙述** | 引导回忆真实经历，讲出来 | 过去时、叙述连贯（用户举的例） | **每天问"今天怎么样"会烦** |
| **纠错反思** | 拿学习者**自己写过的**内容，一起看哪里可以更好 | 元认知、自我修正 | 变成挑错 → 打击 |
| **扩展与升格** | 同一内容换说法/升格（句子 → 段落 → 风格化） | 表达的层次与丰富度 | 拔太高 → 假大空 |

### 3.3 换挡判据（何时该换方法）

换挡不是随机的，由**信号**触发：

| 观察到的信号 | 含义 | 换挡方向 |
|---|---|---|
| 学习者答得太快且全对 | 台子太易 | 升难度 / 换更开放的方法 |
| 学习者沉默、只说"不知道" | 台子太难 或 方法不对路 | 降难度 / 换更结构化的方法（半句接龙、猜词） |
| 同一方法连续 2 次 | 新鲜度耗尽 | **强制换方法** |
| 学习者主动说想学 X | 动机窗口 | 立刻切到他的焦点 |
| 学习者开始用自己的话讲 | 进入表达状态 | **系统闭嘴**，只在被问时帮 |
| 同一错误反复出现 | 真实薄弱点 | 进入刻意复现（见 §5） |

### 3.4 MVP 首批方法（九种不是九种一起做）

九种方法**全做会摊薄**，而且内容资产跟不上时，九种方法 = 空引擎。所以按"**这一种方法必须靠什么知识资产才能成立**"来排优先级。

判据三条：
- **闭环必需**：缺了它，§2.2 的四拍循环走不完。
- **依赖资产少**：不需要先建完大工程才能用。
- **退化风险可控**：不容易滑成 `NON_GOALS` 里否掉的东西。

**首批四种（构成完整闭环）：**

| 方法 | 在循环里担任 | 依赖资产 | 为什么是它 |
|---|---|---|---|
| **回忆叙述** | 用户带内容进来（§2.1 优先级 1） | 只需口语语料 | 唯一能拿到"学习者自己的内容"的方法，是新形态与旧形态的分界 |
| **角色扮演** | 逼产出（主引擎） | 情境库 | 把产出从"被考"变成"要用"；错误在真实交流里自然出现 |
| **情境猜词** | 卡住时的支撑 | 词库（释义面） | 用英文释义代替中文中介；同时是卡住时最有效的降档出口 |
| **扩展与升格** | 收尾成作品（§8） | 表达优化库 | 唯一能产出**可见作品**的方法，"拥有感"靠它 |

**第二批（MVP 验证后再做）：**
- **翻译对照** — 用户自己的内容里暴露出的中式英语，用它来点。**不进首批**：它最容易退化成"逐句批改"，而批改感正是 `NON_GOALS` 要避开的东西。
- **任务驱动** — 与角色扮演同族，成本是"再建一批任务"。有角色扮演之后边际价值低。
- **半句接龙** — 主要用于"沉默"这个信号的降档出口。首批用**情境猜词**兜住这一档即可。
- **纠错反思** — 需要积累若干次会话的历史才有东西可反思，**结构上无法首批**。
- **描述与命名** — 与"情境猜词"职责重叠，且最容易悄悄退回相机中心（把描述变成识物）。重复，后置。

> 结论：**MVP = 回忆叙述 + 角色扮演 + 情境猜词 + 扩展与升格**。四种方法的并集刚好覆盖四拍：诊断（猜词/叙述）→ 搭台（角色扮演）→ 产出（角色扮演/叙述）→ 升格（扩展）。
> §4 的六项知识资产在首批里只需要**词库 + 情境库**两项即可起步；语法点库与表达优化库在"扩展与升格"里小规模用到，可以按需长。

### 3.5 难度分级（静态起点）

§3.3 的换挡是**动态**调节（根据信号换方法）。但还需要一个**静态**起点：同一个"犹豫"，入门和熟练该用完全不同教法。缺了它，系统会对所有人都用同一种难度。

#### 3.5.1 四档（不引入 CEFR 术语）

| 档 | 名字 | 用户能做到什么 |
|---|---|---|
| 1 | **入门** | 会说单词和短句；时态基本靠原形 |
| 2 | **基础** | 能说完整简单句；过去时/复数时对时错 |
| 3 | **进阶** | 能连成段；能用从句；搭配常错 |
| 4 | **熟练** | 表达流畅；要的是地道、精炼、风格 |

#### 3.5.2 起点怎么定（不许考试）

- **靠第一次对话的产出推断**，不问"你什么水平"（自评不准，且像考试）。
- **宁可定低一档**：低一档只是稍微简单，高一档会直接挫败。**挫败的代价远大于无聊。**
- **用户可以自己改**，但系统不主动提"要不要升级"——那会变成分数焦虑。

#### 3.5.3 分档改变什么（同一焦点，四种教法）

以焦点 = `hesitate` 为例：

| 档 | 系统怎么教 |
|---|---|
| 1 入门 | 情境里直接留位置（"Are you sure? — I need to ___."），可给首字母提示 |
| 2 基础 | 给完整情境不给句型；他卡住再给"hesitate 是动词，意思是犹豫" |
| 3 进阶 | 只给情境，并要求他同时用上过去时；反馈时点搭配（hesitate to do / about doing） |
| 4 熟练 | 不告诉他要学什么词，只说"这里有个更精确的说法"；目标是 hesitate vs waver vs vacillate 的语域差别 |

#### 3.5.4 分档也在变（不显示进度条）

- **会话内**：同一焦点连续产出成功 → 升档；连续卡住 → 降档。
- **语言上不说"升级了"**：用**行为**表现（台子变难、帮助变少），不用**数字**表现。
  这与 §2.3"不制造焦虑"一致，也与 `NON_GOALS` 一致：**给的是难度自适应，不是分数**。

### 3.6 框架约束模型（全稿差异化的落点）

用户要求：*「模型采用我们应用的特殊框架约束，并拥有英语专精知识库支撑」*。这是产品唯一的护城河——**不是模型本身**（谁都能调），而是**约束模型的方式 + 喂给它的知识**。

三条原则：
- 模型**不自由发挥**教学内容：教什么由**知识资产 + 学习者状态**决定。
- 模型的职责 = 在给定焦点与方法下**生成这一次的话术**，并按框架要求**选择引导动作**。
- 因此提示词不是"你是一个英语老师"，而是"你在这套框架的第 N 拍，用第 M 种方法，针对焦点 F，学习者当前状态 S，产出下一步"。

#### 3.6.1 提示词槽位（固定六项，不可省）

| 槽位 | 内容 | 缺失后果 |
|---|---|---|
| 拍子 | 诊断 / 搭台 / 逼产出 / 给帮助 / 升格 | 模型不知道自己在流程哪一步 → 一次给完 |
| 方法 | §3.2 九种之一 | 退化成通用闲聊 |
| 难度档 | §3.5 四档之一 | 对入门者讲语域差别 |
| 焦点 | 词 / 结构 / 表达问题 + 来源 | 教学无目标 → 变成空聊 |
| 学习者状态 | 未接触 / 认得 / 能用 | 反复教他已经会的 |
| 情境 | 角色扮演与任务驱动需要 | 台子搭不起来 |

> 注：上表的"方法"槽位对应 §3.4（MVP 首批四种）；§3.2 的九种里其余五种属第二批。本小节的编号为 §3.6.x。

#### 3.6.2 行为约束：四类，必须逐条写

**这才是"框架约束"的实体。** 角色设定（"你是英语老师"）保证不了任何事；行为约束才能。

1. **不许做的事**（负面约束，最有效）：
   - 不许说出焦点词本身（逼产出拍）
   - 不许评价学习者的英语水平、不许打分
   - 不许一次给出多于一个教学点
   - 不许连续追问超过 2 轮（"不审讯"的机械化落地）
   - 不许替学习者写出完整成段范文（除非在"升格"拍且他先产出了）
2. **必须做的事**（正面约束）：
   - 必须为焦点词**留出使用位置**（留白、提问、或情境压力）
   - 单次回复**长度上限**随难度档递减（入门档 = 1-2 句）
   - 卡住时**先降档，不先给答案**
3. **失败时的降级路径**（模型自己判断走不通时怎么办）：
   - 学习者两次沉默 → 降一档难度 → 仍沉默 → 给首字母/给选项 → 仍不行 → **换方法**，而不是继续逼
   - 全程**不许**把"他不会"表达出来
4. **升格路径**：同一焦点连续产出成功 → 会话内升档（§3.5.4）

#### 3.6.3 约束怎么被真正执行（不是靠祈祷）

提示词约束**天然会被模型违反**（尤其"不许说出焦点词"）。三层防护：

| 层 | 机制 | 作用 |
|---|---|---|
| 生成前 | 槽位齐备性检查：六槽任一缺失则不发起调用 | 防"裸聊" |
| 生成后 | **机械校验**：回复里是否出现焦点词（应为空）、长度是否超档、是否出现评分词汇 | 可机读，**可作为测试断言** |
| 违反时 | 重生成一次；再违反则降级为**模板话术**（该方法预置的、不含教学判断的安全句子） | 保证下限 |

> 第二层是这份设计里**少数可被自动化测试钉住的部分**：焦点词泄漏、长度超档、评分词出现——三条都能写成断言。这是把"提示词工程"变成"可验证工程"的关键，也是 `tests/` 在新形态下的立足点。

#### 3.6.4 一个完整的槽位填充示例（入门档）

```
【拍子】逼产出
【方法】角色扮演
【难度档】1 入门
【焦点】hesitate（词）—— 来源：用户今天的内容"我今天犹豫了很久要不要请假"
【学习者状态】未接触
【情境】房东问你还要不要续租

【必须】你只演房东，说 1-2 句；为 hesitate 留出使用位置（如 "Are you sure? Take your time."）；
【禁止】说出 hesitate；评价他的英语；超过 2 句；追问超过 2 轮；
      给整段范文；一次引入第二个词
【卡住时】先给首字母 h___，再给中文提示，再换方法（情境猜词）
```

对照同焦点的**熟练档**：不说是哪个词，只说"这里有个更精确的说法，比 you paused 更贴你的意思"，并要求他比较两个候选词的语域。

## 4. 知识资产（新形态的必备品，现有仓库一条都没有）

| 资产 | 内容 | 为什么必须有 |
|---|---|---|
| **重点词库** | 词 + 词族 + 搭配 + 例句 + **易混词对比** | 判断"哪些值得教"；避免教了冷僻词 |
| **语法点库** | 点 + **中国人常错模式** + 最小对比对 | 精准命中"你这一句里的那个点"，而不是讲一章语法 |
| **表达优化库** | 中式英语典型模式 → 地道替换路径 | 这是"优化表达"能成立的前提 |
| **阶梯框架** | 每层的引导话术与推进判据 | §3 的方法库需要它来落地 |
| **情境库** | 生活化情境（居家/通勤/职场/餐饮…），每个情境带可用词与结构 | 角色扮演/任务驱动需要现成台子 |
| **学习者长期语料** | 他写过的每一天、犯过的错、用过的词 | **产品最值钱的资产**；"循序渐进"的前提 |

> ⚠️ 这六项里，前三项是**内容工程**，不是写代码。需要在计划里单独排期与定验收口径——否则会变成"先写引擎，内容永远没到位"。

---

## 5. 复现：从"排期驱动"改成"对话内自然复现"

现在 `scheduler.mjs` 是 1/3/7 天固定间隔、到点催。在新形态里：
- **复现的载体是对话**，不是提醒。系统在新情境里**自然要求**用上旧词（"你上次说你去看了电影——这次用英文讲讲那次电影"）。
- 固定间隔**可以作为后台线索**（何时该把某个旧词编进新情境），但**不作为对用户的指令**（不发"该复习了"）。
- 代价：现在 `dueWords` / `stage` / 到期徽标这一整条**用户可见的排期面**要退场或彻底重做。

## 8. 作品化：不靠进度条解决"拥有感"

`IN_SCOPE` 已承诺「个人进度与已掌握词可视化」。新形态下最强的可视化不是图表，而是：

> **回看你自己的作品。** 你第一天写的东西、系统陪你改过几轮、现在你能怎么写同一件事——这本**你自己的英文日记**就是进度。

好处：同时解决"拥有感"与"留存来源"（留存来自**这是我写的东西**，而非打卡），并且与 `NON_GOALS` 不冲突。

## 9. 待回答的问题（新契约要回答什么）

旧 `GOAL` 要回答"成人愿不愿意为一次取词举起手机拍一下"。新形态下这个问题**失效**，需要换成：

1. 成人愿不愿意**每天花几分钟把自己的生活用英语说一遍**？
2. **引导式对话**能不能让他持续产出（而不是三天后放弃）？
3. 经过若干次对话，他的**表达**（用词/搭配/连贯）是否可观测地变好？

> 这三条才是新契约的验收命题，且第 3 条可以机读（对同一内容的前后产出做对比），不依赖人工评分。

## 10. 数据模型草案（待细化）

```
焦点 Focus      : { kind: 词|结构|表达问题, ref, 来源: 用户|系统, 状态: 未接触|认得|能用 }
会话 Session    : { 日期, 内容来源, 焦点列表, 走过的拍子, 用过的方法 }
学习者画象      : { 已能用/认得的词, 反复出错的结构, 已用过的方法(防重复), 偏好 }
作品 Work       : { 原始内容, 各层版本(词/句/语法/故事/风格), 修改痕迹 }
```

关键约束：**方法使用记录必须持久化**——否则"连续 2 次同方法就换挡"无法实现。

## 11. 风险（必须先摆平，否则形态定了也落不了地）

1. **自带 Key 的成本结构变了。** 现在是两次调用/词；对话形态是**一次会话多轮调用**。对免费试用的心理门槛是实质抬高的——陌生人要拿自己的钱跑一段不知道多长的对话。需要明确：一次会话的调用上限与用户可见的成本预期。
2. **`NON_GOALS` 撞车（每日任务）**。"每日任务"极容易滑向打卡；必须写死"无连续天数、无断签惩罚"。它只能是"每日一次引导"，不是"任务"。
3. **长期语料 = 全部价值，但现在没有账号。** spec 明确不做账号体系（设备本地 ID）。在识物工具里这没问题；在"陪你学三个月"的产品里，**清一次浏览器数据就清空三个月积累**。这条从"可接受取舍"升级为**产品级风险**，需要正面处置（导出/导入至少要能在册）。
4. **内容工程会被无限推迟。** §4 前三项是内容，不是代码。若不在计划里单列，引擎会先写完而词库/语法库/优化库永远半成品。
5. **"闭嘴"很难实现。** §2.3 要求系统在学习者进入表达状态时停止纠正，§3.6.2 要求"不许说出焦点词""不许连续追问"。这类**负面约束是提示词工程里最容易失效的一类**——模型会本能地"帮忙帮到底"。
   - 缓解：§3.6.3 的三层防护把其中三条做成了**机械可校验**（焦点词泄漏 / 长度超档 / 评分词出现），因此**可写测试断言**。这是把提示词工程变成可验证工程的关键。
   - **仍不可机读的部分**：台子搭得好不好、难度是否真的合适、引导是否让人烦——这三条只能靠真实使用观察，属 `HUMAN_EVALUATION`。
6. **方法库会无限膨胀。** §3.2 是九种，但"提问方法"这个空间是开放的，很容易变成"再加一种方法"的仓库。§3.4 定了首批四种，**但没定"什么时候允许加第五种"的判据**——需要在计划里补一条准入门槛（例如：现有某种方法被证明在某类焦点上系统性失效，才加新的）。
7. **内容资产的正确性无人背书。** §4 的词库/语法库/表达优化库由谁产出、按什么标准验收？**英语教学质量是产品的命**，而这些资产既不是代码也不是测试——如果它们错了，引擎再好也在教错的东西。这条是本形态**最容易被低估的风险**：它需要一条**内容审校流程**（谁审、审什么、错了怎么召回），而现在完全没有。
