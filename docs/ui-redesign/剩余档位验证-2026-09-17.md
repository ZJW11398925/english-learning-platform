## 4. 发现的问题（分级 + 复现步骤）

### 重要 1 —— `word` 屏那个"要学的词"用的是无衬线，与明文口径不一致

- **现象**：`word` 屏的 `h2`「mug」渲染成**系统无衬线**，不是衬线。实测 computed：
  `font-family: system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif`。
- **与什么冲突**：`web/styles.css:10` 的文件头口径「**要学的那个英文词用衬线**，与周围的中文界面分开——它同时是一次语义提示（"这是要记的东西"）和零成本的身份感」；
  `DEC-…b3.44` 的原话「要学的英文词用系统衬线、中文界面用系统无衬线」。`word` 屏的主标题正是"要学的那个词"。
- **落地情况**：`--font-word` 目前只用在两处——`.choices > button`（候选词，**实测是衬线**）与 `.pending-item > p:first-child`（待补原句）。
  `word` 屏的 h2 落在通用 `h2` 规则上（`styles.css:151`），那里没有 `font-family`。
- **复现**：`node tmp/serve-web.mjs 4189` → 打开 `http://127.0.0.1:4189/gallery.html?scenario=word` →
  `playwright-cli -s=ui eval "() => getComputedStyle(document.querySelector('#app h2')).fontFamily"`（或看 `state-word.png`：`mug` 与周围中文同一副字面）。
- **建议**：这是一条**口径/实现二选一**的裁决，不是我能自己定的：
  (a) 补一条 CSS（**不改 app.mjs**，不与现有断言冲突）——
  ```css
  #app > div > h2:has(+ p.muted) { font-family: var(--font-word); }   /* ❌ 太脆，别用 */
  ```
  更稳的形态是给 `h2` 加一条英语词专用规则，但 `app.mjs` 没给 `word` 屏的标题任何类名，**纯按 DOM 形状认它是不可能的**（`word` 的 h2 与 `composing` 的 h2 祖先链完全一样，唯一差别是 `word` 屏多一个 `img`）；
  (b) 或者把口径收窄成"只有候选词与待补原句用衬线"（改 `styles.css:10` 与 `DEC-…b3.44` 的表述）。
  **我倾向 (b)**：`word` 屏是"取到词了"的确认屏，标题用界面同一副字面并不难看，而 (a) 需要动 DOM（红线禁止）或写一条脆判据。

### 重要 2 —— 主流程屏（`capturing` / `word` / `composing`）的唯一推进按钮没有任何重音

**候选按钮自己那条 `--btn-bg: var(--surface)`**（现在有断言钉住它），而"主操作判据里不许出现 `.choices`"
是**结构性**断言（让判据的适用范围一眼可读），不是再挡一层视觉回归。**已把这条更正写回 `styles.test.mjs` 的注释里**——
