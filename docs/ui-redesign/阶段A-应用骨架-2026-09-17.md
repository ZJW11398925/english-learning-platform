## 2. 架构：壳 + 视图

### 2.1 DOM 分层（`web/app.mjs` 的 `mount()`）

```
#app
├── header.appbar            壳：品牌（场景取词） + 一行状态（今天该复习 N 个词 / 今天没有到期的词）
├── p.muted                  状态行（`状态：ready`，既有）
├── p.error                  报错区（既有，不在 bodyEl 里所以换视图不会丢）
├── div                      ← bodyEl：**只装当前视图**（`replaceChildren` 整体重建）
└── nav.tabbar               壳：四枚页签（首页 / 学习 / 复习 / 设置），固定视口底部
```

`render(state)` 每次做三件事：`renderAppBar()` → `renderNav()` → `bodyEl.replaceChildren(...viewFor(state))`。
应用栏与页签在 `bodyEl` **之外**，所以它们不是"视图的一部分"。

### 2.2 状态模型

| 变量 | 含义 | 与状态机的关系 |
| --- | --- | --- |
| `tab`（`'home'\|'learn'\|'review'\|'settings'`） | **唯一**决定 `bodyEl` 渲染哪个视图 | **正交**：切页签不动 `machine` |
| `tabBeforeSettings` | 进设置屏前待着的那一页（「返回」与保存成功都回到它） | 无关 |
| `viewingPending`（既有） | 待补抽屉：**浮在页签之上**的一层 | 无关 |

分派（`viewFor`，一行一条）：

```js
if (viewingPending) return pendingView();      // 抽屉优先（浮层）
if (tab === 'settings') return settingsView();
if (tab === 'review')  return reviewView();
if (tab === 'home')    return homeView();
return learnView(state);                       // 『学习』页 = 既有那条线性流程
```

### 2.3 为什么这样切

1. **`screen()` 工厂**：拆分前 `view` / `row` / `title` / `hint` / `action` 是 `viewFor` 的局部变量，
   "渲染一屏"与"渲染哪一屏"是同一段代码。现在每个视图各拿一份，**谁也不共享 `row`**
   （共享会让两个视图往同一行动作里塞按钮，而按钮颗数是动作行布局与断言口径的依据）。
2. **`learnView(state)` = 原 `viewFor` 的 338 行 switch 原样搬家**（连注释一起搬）：
   行号 1003→1206，唯一的结构改动是开头的 `const s = screen(); const { view, row, title, hint, action } = s;`
   与结尾的 `return appendTail(s);`。**行为一字未改**——取词的七态、按钮文案、事件口径全部照旧。
3. **`appendTail(s)`**：待补入口 + 诊断页链接 + 设置入口。三样**每屏都挂着**（原口径），
   跟着**页签视图**走（首页 / 学习 / 复习），不跟着设置屏与待补抽屉走——那两屏各自有「返回」，
   在里面再挂一个"打开自己"的入口只会绕圈。这与拆分前的行为**逐字一致**。
4. **设置既是页签也是抽屉**：`goTab('settings')` 是唯一入口（页签按钮与「设置（API Key）」入口按钮
   都走它），进之前记下来处；「返回」与保存成功都回到来处。**「设置（API Key）」这个每屏入口按钮
   保留**——它是 12A 的底线（Key 可能在任何一屏失效），也保住"从 capturing 那一屏去换 Key、
   回来仍在 capturing"这条现场。代价是设置有了两个入口（见 §9 取舍 3）。

### 2.4 首页 / 复习页的内容来源（**一个新数都不造**）

| 显示项 | 来源 |
| --- | --- |
| 应用栏状态行「今天该复习 N 个词」/「今天没有到期的词」 | `dueList()` = `store.readWords()` + `units/scheduler.mjs` 的 `dueWords` |
| 首页到期卡片「今天该复习 N 个词」+ 场景提示 | 同上（**只在 N > 0 时创建这个元素**；0 不写成"0 个词"） |
| 首页「已学 N 个词」+ 词块 | `store.readWords()`（按 `createdAt` 降序、同刻按 id 码位序兜底；最多铺 12 个，其余一句话交代） |
| 复习页「今天该复习 N 个词」 | `dueList()` |

## 4. 测试改动逐条说明

### 4.1 改动原则

- **只有 mount 类测试被改**，且改法只有两种：①在驱动链路前**先导航到学习页**；
  ②断言对象从"首页"换成"默认页"（仅 1 条）。
- **单元测试零改动**：`state-machine` / `store` / `scheduler` / `pending` / `rounds` / `recognize` /
  `compose` / `feedback` / `album` / `camera` / `frame-qc` / `keyring` / `export` / `event-log` /
  `deepseek` / `pick-word` / `storage-full` 一个字节都没动（`git status` 里没有它们）。
- `tests/styles.test.mjs`（17 条静态样式契约）与 `tests/index-html.test.mjs`（4 条结构契约）**零改动**，
  且在新 CSS / 新 DOM 下全绿——那 17 条里的"组件规则不写死颜色""恰好一处重音底色""候选按钮拿不到
  `.primary`"都是我这次必须绕开的硬约束（见 §9 取舍 2）。

### 4.2 新增的导航助手（`tests/helpers/mount-harness.mjs`）

```js
export async function gotoLearn(root) { /* 在 <nav> 里按**精确文案**找「学习」并点它 */ }
export const openCameraAndShoot = async (h) => { await gotoLearn(h.root); /* 拍照 → 快门 */ };
```

两条设计理由（都写进了文件注释）：

1. **为什么必须有它**：非活动视图是**从 DOM 卸载**的（不是 `display:none`），所以 `mount()` 之后
   首页上**真的**搜不到「拍照」——所有驱动取词链路的用例都必须先导航。收成一个**具名**助手，
   读用例的人一眼看得见"这一条从学习页开始"。
2. **为什么取页签不能用现成的 `btn(root, '学习')`**：`btn()` 是 `includes` 匹配，而首页那颗大字入口叫
   **「开始学习」**，它包含「学习」二字；导航条排在内容之后 ⇒ `btn(root,'学习')` 在首页会先命中
   「开始学习」。两枚按钮的文案都被任务书钉死，所以这个歧义只能靠"限定在 `<nav>` 里 + 全等"消掉。
   助手还顺手断言了"页签恰好四枚"（这条断言在变异 M2 上响了）。


- 旧断言：返回之后首页上仍有「拍照」。
- 新断言：返回之后首页上仍有「开始学习」。

  在首页上**按设计不再存在**（取词入口搬进了学习页），所以旧断言的**对象**已经不成立；
  换成的「开始学习」是首页自己的唯一推进入口，等价地钉住"返回没有把这一屏弄坏"。
  同时这一条的语义还**变强**了：它现在验的是"待补入口在**应用真正的第一屏**（默认页）上找得到"，
  而那正是 `mount()` 之后用户第一眼看到的那一屏（`machine.state` 仍是 ready 这一条原样保留）。
- 另外**没有**为了让它变绿而放宽任何东西：`text(root)` 里的原句断言、`（1 条）` 计数断言、
  「返回」按钮存在断言全部原样。

## 9. 判断与取舍（需要人知道的）

1. **切页签不关摄像头（`capturing` 那一格）**。`render()` 关流的判据是**状态机**（离开 `capturing` 这一态），
   不是页签。若把"切走页签"也算成离开：回到学习页时用户会面对一块**死画面**且无路可走
   ——`capturing` 没有回 `ready` 的用户入口（唯一的 `frameBad` 需要真的拍一张、会落一条拒帧事件，
   拿它"收尾"就是伪造记录）。**代价如实登记**：切到别的页签期间摄像头仍开着；回到学习页取景原样还在
   （`videoEl` 是同一个节点，`srcObject` 没被动过；实测 `openCamera` 只调过 1 次）。
2. **首页的「开始学习」不做实心重音**。重音只给"学习流程里那一颗推进按钮"是人裁决
   （`DEC-OPI-968b804d-…db.6`），那张**六屏表**由 `tests/styles.test.mjs` 逐文案钉住，
   并断言"全站被标成主操作的 `action()` 调用点**恰好**那六颗"。让「开始学习」走 `.primary` 会
   要么改那条断言（= 改人裁决钉住的表，任务书不允许我改样式测试）、要么绕过 `action()` 手写类名
   （= 规避测试）。两条都不做：首页入口靠**尺寸**成为这一屏最重的东西（56px / 1.125rem / 更软的圆角）。
   **若人希望它是实心重音**，需要一条新裁决 + 把六屏表扩成七屏——那是裁决不是实现细节。
3. **「设置（API Key）」入口按钮保留**（每屏都挂着），与第四枚页签并存。理由：12A 的底线是
   "Key 可能在任何一屏失效"，且这个入口能把用户送去设置再**原样送回**（`capturing` 现场不丢）。
   代价是设置有两个入口，轻微冗余——阶段 B/C 若要收，需先想清楚"从 capturing 去换 Key 再回来"
   这条现场怎么保住。
4. **应用栏状态行与首页到期卡片会出现同一句话**（应用栏是全局一行状态，首页那条是**带场景提示**的
   可行动版本）。我判断这不值得为去重牺牲"每屏都能看到今天该复习几个"这件事；觉得吵的话删应用栏
   那一行即可（一处样式/一行代码）。
5. **待补入口在复习页上重复**：复习页正文已经写了"待补反馈 N 条"，壳尾又挂一颗「待补反馈（N 条）」。
   保留是因为"每屏都挂着"是既有口径（有 3 条 mount 测试依赖它）。阶段 B 做复习页时再收。
6. **`pending-empty` 档仍然看不到"空的待补抽屉"**（入口按钮只在真有欠账时才渲染，那是产品口径）。
   我把它**实际**到达的那一屏写成了判据并在走查台里说明，**没有**改行为、也没有假装它是空抽屉。

## 10. 未验 / 已知限制（**不要当成已验**）

1. **只有一个引擎**：全部浏览器实测都在 **msedge（Chromium）** 上做的。Firefox / WebKit **未验**
   （本机没装）。`aria-current` 属性选择器、`flex: 1 1 0` 的页签等分、`position: fixed` + `max-width`
   居中的组合在另两个引擎上未测。
2. **真机未测**：390×844 是**桌面 Edge 的移动仿真**，不是真机。触屏热区、软键盘（设置屏的
   `input[type=password]` 弹起时页签会不会被顶上来）、真视频流、`safe-area-inset-bottom`
   （仿真里 env() 恒为 0）**全部未验**。
3. **当前页签对比度 4.84:1** 是浅色下唯一的临界值（刚过 AA 正文线）。深色 7.57:1 无问题。
   我**没有**微调颜色去凑更高的数——因为改它就得动 `--accent-wash` 或换一套高亮形态，
   那是设计口径的改动。如实登记。
4. **`:hover` / `:focus-visible` / `::placeholder` 状态色**仍**未验**（AGENTS.md 里已有的旧缺口，
   本次没有新增证据）。
5. **`--ink-faint` 浅色 2.93:1** 仍未修（人裁决只清零风险三项）——在册未消，本次不碰。
6. **切页签时摄像头不关**这一行为的"耗电/吓人"程度**没有量**——只有"回到学习页现场还在"这一条实测。
7. **词块上限 12 个**这个数字是判断（"一屏能扫完"），**没有实测**超过 12 个词时的排版；
   带 100 个词的首页未截图。
8. **首屏渲染时序**：`renderAppBar()` 每次渲染都读一次 `store.readWords()`（首页/复习页/学习页各再读一次）。
   词表很大时的耗时**没有量**（当前规模下无感）。
9. `pending-empty` 档的"判据补齐"只是把**判据**写对了，它想看的"空抽屉"那一屏**依然不可达**。

## 11. 结论

**阶段 A 的六项要求全部落地并实测**：①应用栏 + 底部四页签（48px 触控目标、全部令牌化）②默认落在首页
（人裁决，为此改了 mount 类测试）③首页四块内容（到期行只在真有到期词时出现、空状态非空白）
④338 行 switch 原样搬进学习页 ⑤`viewFor` 拆成壳 + 视图、非活动视图**从 DOM 卸载**（浏览器实测：
首页 0 颗「拍照」、display/visibility 无从谈起）⑥复习页最小可用（只读既有两个数）。
裸 `node --test` **527 passing / 0 failing**（基线 511 + 新增 16）；单元测试**零改动**；
4 个变异体全部 RED，恢复后 13 个文件 sha256 **逐位复原**；走查台 15 档 15/15 到达、0 报错。
**未验项如实登记在 §10，其中最重要的是：只有 Chromium 一个引擎、没有真机**——
"像不像一个 App"这件事在真机上的答案，本阶段没有证据。
