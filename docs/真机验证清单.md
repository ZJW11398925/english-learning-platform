# 真机验证清单（首条价值切片）

**谁来做**：你（不需要读代码）。
**何时**：Task 7（识物）之后走一遍；Task 8（造句反馈）接上后再走一遍第 16、26 步。
**怎么回报**：按下表的**编号**回报（例如"9 通过""12 失败，提示原文是…"）。**编号在本文件内唯一，不会有歧义。**

**为什么必须人工做**：自动化测试能覆盖纯逻辑与装配，但**相机权限、真机渲染、`getUserMedia` 行为、真实拍照的明暗判定、弱网表现**这几类只能在手机上确认。subagent 已明令不得声称完成这些步骤。

---

## 一、准备（一次性，在电脑上）

| # | 做什么 | 成功的标志 |
|---|---|---|
| 1 | 在项目目录启动服务 | 看到 `listening on http://localhost:8787` |
| 2 | 另开一个终端做内网穿透（cloudflared 或同类） | 拿到一个 **`https://` 开头**的公网地址 |
| 3 | 手机连同一个 Wi-Fi，用手机浏览器打开**那个 `https://` 地址** | 页面出现 |

> ⚠️ **不要用 `http://` + 电脑局域网 IP**。浏览器只在安全上下文（`localhost` 或 HTTPS）下放行相机，用 IP 一定失败。

## 二、手机上的基础检查

| # | 检查项 | 预期现象 |
|---|---|---|
| 4 | **页面出得来** | 看到标题「拍一件你身边的东西」与「拍照」按钮；不是空白、不是报错页 |
| 5 | **相机能唤起** | 点「拍照」→ 浏览器询问相机权限 → 允许 → 出现**实时画面**（不是黑屏、不是全屏播放器页） |
| 6 | **用的是后置摄像头** | 画面是手机背面那颗镜头看到的，不是自拍镜头。若不对，记录手机型号与浏览器版本 |
| 7 | **权限被拒的表现** | 先把本站点相机权限改成"拒绝"，再点「拍照」→ 应提示"相机没有授权…"，状态停在初始页且**「拍照」按钮还在**。**不应**出现任何"跳过/随便看看"入口 |
| 8 | **按快门能冻结画面** | 对准物体点「快门」→ 1～2 秒内跳下一屏，显示**刚才那一帧静止画面**（非实时画面） |
| 9 | **太暗会被退回** | 用手完全挡住镜头再拍 → 退回初始页并提示"刚才那张太暗…"，**不是**跳到"取到的词" |
| 10 | **太糊会被退回** | 对着白墙或纯色平面（无纹理）拍 → 退回并提示"有点糊…" |
| 11 | **重拍能连续进行** | 被退回后立刻再拍，重复 3 次不卡死、不白屏 |
| 12 | **按太早的表现** | 刚进拍摄画面、画面还没出来时连点「快门」→ 提示"画面还没准备好，请稍等一秒"，**不应**跳到"取到的词" |
| 13 | **摄像头灯会灭** | 从拍摄屏跳到"取到的词"后，状态栏/刘海处**相机指示灯应熄灭**（若一直亮，记录机型） |
| 14 | **双击不会卡住** | 初始页快速双击「拍照」→ 正常进入拍摄画面，不出现两路画面或两次权限弹窗 |
| 15 | **屏幕适配** | 内容不被刘海/挖孔挡住；按钮与输入框不超屏；横竖屏切换不破版 |
| 16 | **整个骨架能走完** | 拍照 → 快门 → 「我会读了」→「跳过跟读」或「我读完了」→ 写一句英文 →「提交造句」→「再写一次」（**输入框应带出上一版原文**）→「提交造句」→「下一个词」→ 完成页显示指标 |
| 17 | **刷新页面后** | 回到初始页（当前不跨页面保存进度）；**相机权限不应再次询问** |

> ⚠️ **第 16 步完成页的「改写」数字**：提交 2 次（回改 1 版）应显示「改写 **1** 次」。早期文档曾写「改写 2 次」，那是把提交次数误当改写次数的旧缺陷（已修）——**照旧文走查会误报一个已经修好的问题**。

## 三、识物链路（Task 7，手机上是必看项）

| # | 检查项 | 预期现象 |
|---|---|---|
| 18 | **识物真的能取到词** | 对准一个马克杯 → 按快门 → 1–3 秒后出现一个**具体的英文名词**（`mug` / `cup`），并写明"场景：…"与"第 N 次尝试取到"。**不应**出现 `container`、`object`、`thing` 这类上位词——那些被 `pickWord` 挡掉了，出现即缺陷 |
| 19 | **取不到词时降级为手选，且不假造** | 对着模型多半认不出的东西拍（纯色墙面、手掌、模糊远景）→ 两轮尝试后显示"**没能自动认出这个词**"，下面是可点的英文词与「再拍一张」。**这一屏不许出现任何"识别出来的词"** |
| 20 | **手选的词明说是手选** | 在第 19 步的列表里点一个词 → 标题变成那个词，下面必须写"**这是你自己挑的词，不是识别出来的**"。缺这句即把手选冒充成了识别结果 |
| 21 | **「再拍一张」立刻重来** | 在 19/20 那屏点「再拍一张」→ **立刻再拍一帧并重走一次识物**。连点两三次不卡死、不白屏 |
| 22 | **识别失败 ≠ 帧被拒** | 走完第 19 步后看完成页：「被退回的帧」应**只**统计太暗/太糊，不把识物失败算进去 |
| 23 | **弱网/服务端卡住不会永久卡死** | 在信号很差的角落（或先把电脑上的服务停掉）按一次快门 → 最多等十几秒就回到"**没能自动认出这个词**"，**不会**无限期停在拍摄画面。这一屏仍要有手选词包与「再拍一张」——**"等太久"必须是一条有出口的失败，不是卡死** |
| 24 | **等待期间连点快门不会堆积** | 在第 23 步那种"等很久"的情形里连点几次「快门」 → 每次点击各自走到一个结论，**不应**"点了没反应、越点越卡"。服务端日志里每次识物请求也应有收尾 |
| 25 | **重拍次数数得对（判据 B 的输入）** | 走第 11 步（连续重拍 3 次）后，电脑上开开发者工具 → Application → Local Storage → 键 `elp.events`：每次快门应恰好**一条**结论事件（`frame_rejected`/`recognize_ok`/`recognize_failed` 三选一），`roundIndex` 为 **1、2、3…** 逐次加一。**一次快门里模型被问两次时 `payload.attempts` 会是 2，但 `roundIndex` 只加 1**——两个数必须分开看（判据 B 用的是 `roundIndex`） |

## 四、额度与安全（电脑上做，不用手机）

| # | 检查项 | 预期现象 |
|---|---|---|
| 26 | **被拒的帧不花额度** | 对着纯黑/纯色拍，看到"太暗/太糊"后回电脑看服务端终端日志 → **没有任何识物相关日志行**。若出现 `recognize 失败`/`识物请求`，说明前置拦截失效，额度会白花 |
| 27 | **垃圾字节不花额度** | `curl -i -F "image=@package.json;type=image/jpeg" http://localhost:8787/api/recognize` → `400` + `{"error":"bad_request"}`，且服务端**没有任何上游调用**（魔数校验拦下了） |
| 28 | **畸形请求不打死服务** | `curl -i "http://localhost:8787//"` → `400 Bad Request`，且服务**仍在运行**（随后正常访问页面仍可用）。修复前这一条会让服务进程 `exit 1` |
| 29 | **手选不污染识别成功率** | 走完第 19–20 步后翻查 `elp.events` → 这一轮落的是 `recognize_failed`（带 `reason`），**不是** `recognize_ok`。若手选也记了 `recognize_ok`，识物成功率会被手选污染 |
| 30 | **隧道期间的额度消耗** | 服务开着隧道时，确认是否有他人/扫描器调用 `/api/recognize`、`/api/feedback`。**没有图片的请求会直接 400、不打上游**（扫描器打不穿），但**带图片的请求会真的调用模型**，按次计费。**若长时间挂公网，需加访问口令或限流，或只在测试时开、用完即关** |

## 回报什么

1. **手机型号 + 浏览器与版本**（第 6、13 项需要）
2. 每一步的**编号**与实际现象：成功 / 失败 / **提示原文**
3. 任何"没有反应"或白屏的时刻
4. **即使全部通过也要回报"全部通过"** —— 沉默无法区分"通过"与"没测"

## 已知的、不算问题的现象

- **第 9/10 步的阈值**（亮度 40 / 清晰度 80）是**首轮设定值，未经真实数据校准**。若你觉得明显偏松或偏严（例如正常室内光也被判太暗），**如实记录当时的场景与现象**——这正是首周校准要用的数据。
- **第 23 步最坏会等约 24 秒**（客户端超时 12 秒 × 两轮尝试）。这个上限也是首轮设定值，**目前没有"正在重试"的进度提示**，所以等待期间界面看起来是静止的。若你觉得体感过长，请记录当时的网络状况——这是调参依据。
- **第 31 步没存句子**：Task 9 之前属已知状态。
- **第 25 步的 `attempts` 可能大于 1**：同一帧最多问两次模型，这是有意的（不做自动连拍，重拍由你决定）。
