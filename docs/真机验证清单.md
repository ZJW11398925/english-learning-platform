# 真机验证清单（详版 · 照着做即可）

> 这份清单是给**你**用的，不是给程序员看的。它假设你**完全没有技术背景**。
> 你只需要：会打字、会点手机、会复制粘贴。**不需要看懂任何代码。**

---

## 〇、先读这一段（1 分钟）

### 这是什么

我们做了一个学英语的手机网页应用：对着身边的东西拍一张照，它给你对应的英文词，你跟着读一遍，然后**自己写一句英文**，它给你反馈。

自动测试已经跑了几百项，但有几件事**只能在真手机上验证**——相机能不能打开、拍照判定准不准、弱网会不会卡死。这份清单就是让你去确认这些。

### 需要多长时间

**第一次做约 40–60 分钟**（含配置电脑）。如果只是复查某几步，10 分钟够。

### 你需要准备

| 东西 | 说明 |
|---|---|
| 一台电脑 | Windows 即可 |
| 一部手机 | 能连 Wi-Fi、有摄像头 |
| 同一个 Wi-Fi | 电脑和手机必须连**同一个** Wi-Fi |
| 电脑上的终端窗口 | Windows 上叫 **PowerShell**（开始菜单搜"PowerShell"就能找到）。下面简称"终端" |
| 一个浏览器 | 电脑上用来查记录的（Chrome / Edge 都行） |

### 两个"屏幕"，别搞混

| 屏幕 | 用来做什么 | 对应哪些步骤 |
|---|---|---|
| **电脑上的终端**（黑底白字那个窗口） | 启动服务、看日志、看记录 | 第 1–3、26–30 步 |
| **手机上的浏览器** | 真正试用这个应用 | 第 4–25、31–38 步 |

### 怎么用这份清单

- **按编号顺序做**，不要跳。编号是**唯一**的，回报时直接说编号即可。
- 每一步都给了四件事：**要做什么 → 成功的样子 → 失败的样子 → 记什么**。
- **遇到失败不要自己想办法修**。如实记下"编号 + 你看到的原话"，继续往下做。
- **做完把最后的表格填好发我**。哪怕全部通过也要发——只发"通过"两个字也行，但**别不发**：不发我无法区分"通过了"和"没测"。

### 复制粘贴怎么做

清单里凡是带灰底的文字，都是让你**复制到终端里回车**的。做法：

1. 鼠标选中那行文字 → 按 `Ctrl + C`
2. 切到终端窗口 → 按 `Ctrl + V` → 按回车

> ⚠️ 如果粘贴没反应，在终端窗口里**点一下鼠标右键**试试。

## 一、准备（电脑上做，第 1–3 步）

> **推荐方式：本机 HTTPS + 手机直连局域网**（不依赖任何第三方，最稳）。
> 隧道方式（cloudflared / ngrok / localtunnel）在本机环境均不可用，原因见第六节排障表。
> 下面第 2–3 步是**直连方式**；若你仍想用隧道，见本节末尾的备注。

### 第 1 步 · 找到项目文件夹

**要做什么**：确认项目在 `D:\测试1`。在终端里输入下面这行并回车：

```
cd D:\测试1
```

**成功的样子**：终端左边显示路径变成了 `D:\测试1>`，没有任何红色报错。

**失败的样子**：出现"找不到路径""系统找不到指定的文件"。

**记什么**：成功记 ✓；失败把红色文字原样抄下来。

---

### 第 2 步 · 启动服务（HTTPS 版）

**要做什么**：在终端里输入下面这行并回车：

```
node --env-file=.env server/https-local.mjs
```

**成功的样子**：终端输出类似下面几行（IP 会是你的实际局域网地址）：

```
HTTPS 已启动，监听 0.0.0.0:8443
  手机可访问（WLAN）: https://10.68.199.114:8443
  本机自测: https://localhost:8443
```

并且**光标停在下面不再动**（正常，服务正在运行）。

**记什么**：把「手机可访问（WLAN）」那一行的 `https://…:8443` **抄下来**，第 3 步要用。

> ⚠️ **这个终端窗口从现在起不要关、不要按 Ctrl+C**。关了服务就停了，手机上会打不开。
> 后续要看日志就用这个窗口；要**输入别的命令**，就**再开一个新的终端窗口**（开始菜单再搜一次 PowerShell）。

**记什么**：成功记 ✓；失败抄原话。

---

### 第 3 步 · 手机连接（直连局域网，不用隧道）

**为什么可以直接连**：第 2 步起的是**HTTPS 服务**（`https://…:8443`），已经满足"安全上下文"这个前提。手机和电脑在同一个 Wi-Fi 下，直接访问电脑的局域网地址即可——**不需要任何隧道**。

**要做什么**：

1. **确认手机和电脑连的是同一个 Wi-Fi**（这一步最容易出错：手机若开着流量或连了别的 Wi-Fi，就连不上）。
2. 手机浏览器地址栏输入第 2 步抄下来的那个地址，例如：

```
https://10.68.199.114:8443
```

3. **首次会提示"证书不受信任"**——这是**正常的**，因为证书是你这台电脑自己签的（没有花钱买）。处理方式见第 3.5 步。

**成功的样子**：页面出现（标题「拍一件你身边的东西」+「拍照」按钮）。**注意：必须先解决证书警告**，否则浏览器会拦住页面。

**失败的样子**：

- 提示"无法访问此网站" → 多数是手机不在同一个 Wi-Fi，或电脑上第 2 步的服务停了。
- 一直转圈 / 提示连接超时 → 检查电脑的防护软件或 Windows 防火墙是否拦了 node（首次运行时通常弹窗询问，要选"允许"）。

### 第 3.5 步 · 装证书（一次性，装完以后不再有警告）

> 这步只是**让浏览器信任你自己签的证书**，不装也能用（每次手点"继续访问"），但**相机可能被浏览器拦住**，所以建议装。

**先做**：让手机能下载到证书文件。在电脑上**新开一个终端窗口**，输入：

```
cd D:\测试1\.certs
npx --yes http-server -p 8899
```

（等它输出几行，别关这个窗口）

然后**在手机浏览器里**打开：

```
http://10.68.199.114:8899/手机要装的证书.crt
```

手机会下载这个文件。然后按你的手机系统操作：

**iPhone / iPad**：

1. 下载后会出现"已下载描述文件"→ 打开**设置**
2. 设置 → 通用 → **VPN与设备管理** → 点刚下载的那个描述文件 → 安装（要输锁屏密码）
3. **还有一步不能漏**：设置 → 通用 → 关于本机 → 拉到底 → **证书信任设置** → 把刚才那个证书的开关**打开**
4. 回到浏览器刷新页面，警告消失

**安卓**：

1. 下载后打开**设置** → 安全 → **加密与凭据** → 安装证书 → **CA 证书** → 选择刚下载的文件
2. 会提示"你的数据可能被监控"之类——这是系统对 CA 证书的常规警告，选**继续安装**
3. 回到浏览器刷新页面（安卓部分机型/浏览器仍会显示警告，手点"继续访问"即可）

**做完之后**：把第 3.5 步这个下载证书的终端窗口**关掉**（按 `Ctrl + C`）——它只为传证书用，不需要一直开着。

**记什么**：✓ 页面能正常打开、没有警告；✗ 记下警告原文或卡在哪一步。

2026-09-15 实测结论：

| 方案 | 结果 | 原因 |
|---|---|---|
| `cloudflared tunnel --url http://localhost:8787` | ❌ 必然失败 | 本线路到 Cloudflare 接口固有延迟约 6 秒（直连 5.8s / 走代理 6.4s），超过其内部约 5 秒超时 |
| `ngrok http 8787` | ❌ 不可用 | 本机有代理客户端 `monocloud`（系统代理 `127.0.0.1:10801`），而 ngrok 把"代理下运行"列为**付费功能**（`ERR_NGROK_9009`） |
| `npx localtunnel --port 8787` | ⚠️ 时好时坏 | 手机首次访问会撞上防滥用认证页（要填本机公网 IP `103.230.68.65`），且会自动断线 |

所以**用上面的直连方式**。若将来网络环境变了（例如 Cloudflare 延迟降回 1–2 秒），三条命令都仍可用。

</details>

**记什么**：把手机能打开的那个 `https://…:8443` 地址确认下来。

## 二、手机上的基础检查（第 4–17 步）

> 从这一步开始**换到手机操作**。手机必须连**和第 1、2 步那台电脑同一个 Wi-Fi**。

### 第 4 步 · 打开页面

**要做什么**：

1. 手机浏览器（Safari / Chrome / 系统自带都行）地址栏里**输入第 3 步拿到的那个 `https://` 网址**
2. 回车

**成功的样子**：页面出现，有一个大标题，大意是"**拍一件你身边的东西**"，下面有一个「**拍照**」按钮。

**失败的样子**：白屏 / "无法访问此网站" / 一直转圈。

**如果失败**：先检查第 2 步那个终端窗口还在不在（关了就要重开）。还不行就记下来发我。

**记什么**：✓ 或 ✗ + 你看到的文字。

---

### 第 5 步 · 相机能不能打开

**要做什么**：点一下「**拍照**」按钮。

**成功的样子**：浏览器弹出询问"是否允许使用摄像头"，点**允许**之后，屏幕上出现**实时画面**（能看到你面前的东西在动）。

**失败的样子**：

- 没弹出权限询问，直接白屏
- 弹出了但点"允许"之后还是黑的
- 出现一整屏全屏播放器的样子（带进度条那种）

**记什么**：✓ 或 ✗ + 描述你看到什么。

---

### 第 6 步 · 用的是后置摄像头

**要做什么**：看画面——是不是手机**背面**那颗镜头看到的（对着桌面/房间），而不是前置自拍镜头。

**成功的样子**：画面是你面前的环境。

**失败的样子**：画面是你的脸（前置镜头）。

**记什么**：✓ 或 ✗ + **手机型号**（例如"小米 14""iPhone 15"）+ **浏览器**（Safari / Chrome / 微信内置浏览器…）。

> 这一项的机型信息很重要，我需要知道是哪台手机翻了。

---

### 第 7 步 · 拒绝相机权限时会怎样

**要做什么**：

1. 先在浏览器设置里，把**本站点**的摄像头权限改成"**拒绝**"
   - Chrome：地址栏左边有个锁/信息图标 → 点开 → 权限 → 摄像头 → 改为"阻止"
   - Safari：设置 → Safari → 相机 → 改为"拒绝"（或直接在页面弹窗里选"不允许"）
2. 回到页面，再点「**拍照**」

**成功的样子**：出现一句话，大意是"**相机没有授权…请在站点设置里允许摄像头**"，页面**仍停在初始页**，「拍照」按钮**还在**。

**失败的样子**：

- 出现"跳过"/"随便看看"/"直接开始"之类的入口（**这绝对不该有**）
- 「拍照」按钮消失，页面变成死页面

**记什么**：✓ 或 ✗ + 提示的原话。

**做完记得**：把权限改回"允许"，不然下一步做不了。

---

### 第 8 步 · 按快门能"冻住"画面

**要做什么**：对准一个真实物体（比如一个杯子），点屏幕上的「**快门**」。

**成功的样子**：1–2 秒内跳到下一屏，显示**刚才那一帧的静止画面**（不再动），并且有一个**具体的英文单词**（对着杯子应该是 `mug` 或 `cup`）。

**失败的样子**：

- 一直停在实时画面不动
- 显示的画面还在动（没冻住）
- **出现英文词但你没拍到任何东西**（这是严重缺陷）
- 出现 `container`、`object`、`thing` 这类"笼统的词"（这些词被代码挡掉了，出现即缺陷）

**记什么**：✓ 或 ✗ + 你看到的英文词是什么。

> 💡 **看不到英文词怎么办**：那说明识物没成功，页面会显示"**没能自动认出这个词**"并给一排可点的词。这不算失败，**算第 19 步**，你直接跳去做第 19 步。

---

### 第 9 步 · 太暗会被退回

**要做什么**：用手**完全挡住**摄像头镜头，然后点「**快门**」。

**成功的样子**：页面**退回初始页**，并出现一句提示，大意是"**刚才那张太暗…**"。

**失败的样子**：跳到"取到的词"那一屏（说明没拦住，暗照片被当成正常照片送出去了）。

**记什么**：✓ 或 ✗ + 提示原话。

---

### 第 10 步 · 太糊会被退回

**要做什么**：对着**白墙**或**纯色桌面**（没有花纹、没有东西的地方）拍一张。

**成功的样子**：退回初始页，提示大意是"**有点糊…**"。

**失败的样子**：跳到"取到的词"那一屏。

**记什么**：✓ 或 ✗ + 提示原话。

---

### 第 11 步 · 能连续重拍

**要做什么**：在刚才被退回的地方，**连续做 3 次**：点「拍照」→ 点「快门」→（被退回）→ 再点「拍照」…

**成功的样子**：3 次都能正常走，不卡、不白屏、按钮都还能点。

**失败的样子**：某一次点了没反应 / 白屏 / 按钮消失。

**记什么**：✓ 或 ✗ + 第几次出问题。

> 💡 **这一步顺便为第 25 步做准备**：你按了几次快门，第 25 步要去电脑上核对记录。心里记一下次数。

---

### 第 12 步 · 按得太早会怎样

**要做什么**：点「拍照」进入拍摄画面后，**趁画面还没出来**，立刻连点几次「快门」。

**成功的样子**：出现提示，大意是"**画面还没准备好，请稍等一秒**"，**不会**跳到"取到的词"。

**失败的样子**：跳到"取到的词"那一屏（说明它把一张空照片当成正常照片了）。

**记什么**：✓ 或 ✗ + 提示原话。

---

### 第 13 步 · 摄像头指示灯会灭

**要做什么**：从拍摄画面跳到"取到的词"那一屏之后，**看手机屏幕顶部状态栏/刘海位置**。

**成功的样子**：相机指示灯（通常是一个绿色或橙色小圆点）**熄灭了**。

**失败的样子**：灯一直亮着（说明摄像头没被释放，会耗电）。

**记什么**：✓ 或 ✗ + 手机型号。

---

### 第 14 步 · 双击不会卡住

**要做什么**：回到初始页，**快速连点两下**「拍照」。

**成功的样子**：正常进入拍摄画面。不会出现两路画面、也不会弹两次权限询问。

**失败的样子**：出现两个画面 / 两次权限弹窗 / 卡住。

**记什么**：✓ 或 ✗。

---

### 第 15 步 · 屏幕适配

**要做什么**：随便看看页面。

**成功的样子**：

- 内容没被刘海/挖孔挡住
- 按钮、输入框都在屏幕范围内，没有跑到屏幕外
- 把手机横过来再竖回去，页面没乱

**失败的样子**：有内容被挡住 / 按钮超出屏幕 / 横竖切换后布局坏了。

**记什么**：✓ 或 ✗ + 哪里不对。

---

### 第 16 步 · 走完整个流程

**要做什么**：按顺序点：

1. 拍一张能认出来的东西（例如杯子）→ 点「快门」
2. 出现词之后 → 点「**我会读了**」
3. → 点「**跳过跟读**」或「**我读完了**」
4. → 在输入框里**写一句英文**，例如 `I use a cup.`
5. → 点「**提交造句**」
6. → 等反馈出来后，点「**再写一次**」
7. → **检查输入框**：应该**自动带出你刚才写的那句话**（不用重打）
8. → 再点一次「**提交造句**」
9. → 点「**下一个词**」
10. → 出现"完成"页，上面有几个数字

**成功的样子**：最后那页显示「**改写 1 次**」之类的指标（你提交了 2 次 = 回改了 1 版）。

**失败的样子**：

- 中间任何一步点了没反应
- 第 7 步输入框是空的（要重打）
- 完成页没有数字 / 数字不对

**记什么**：✓ 或 ✗ + 卡在第几步 + 完成页上都有哪些数字。

> ⚠️ **注意**：完成页显示的应该是「改写 **1** 次」。如果你看到「改写 2 次」，那是一个**已经修好的旧缺陷**又回来了——请务必记下来。

---

### 第 17 步 · 刷新页面

**要做什么**：把手机浏览器这个页面**刷新一下**（下拉刷新或点刷新按钮）。

**成功的样子**：

- 回到初始页（目前的版本不保存进度，这是正常的）
- **不会再问一次相机权限**（浏览器记住了你的授权）

**失败的样子**：又弹一次权限询问 / 白屏 / 报错。

**记什么**：✓ 或 ✗。

---

## 三、识物链路（第 18–25 步）

### 第 18 步 · 识物真的能取到词

**要做什么**：对准一个**马克杯**（或任何杯子），点「快门」。

**成功的样子**：

- 1–3 秒内出现一个**具体的英文名词**（`mug` / `cup`）
- 标题下面有一行写着"**场景：**…"和"**第 N 次尝试取到**"

**失败的样子**：

- 出现 `container`、`object`、`thing` 这类笼统词
- 出现词但下面没有"场景"和"尝试次数"的说明
- 等了很久没有反应（→ 见第 23 步）

**记什么**：✓ 或 ✗ + 出现的词。

---

### 第 19 步 · 认不出来时会给手选，且不假装认出来了

**要做什么**：对着一个**模型大概认不出的东西**拍——例如纯色墙面、你的手掌、很模糊的远景。

**成功的样子**：

- 等两轮尝试之后，出现"**没能自动认出这个词**"
- 下面是一排**可以点的英文词**（`mug` `cup` `book`…）
- 还有一个「**再拍一张**」
- **这一屏不许出现任何"识别出来的词"**（因为确实没识别出来）

**失败的样子**：这一屏出现了一个英文词，但你没有手选过（那就是在假装识别成功）。

**记什么**：✓ 或 ✗ + 屏幕上出现了什么。

---

### 第 20 步 · 手选的词会明说是你挑的

**要做什么**：在上一屏那排词里，**点一个词**。

**成功的样子**：

- 标题变成你点的那**那个词**
- 下面有一行明确写着"**这是你自己挑的词，不是识别出来的**"

**失败的样子**：没有那句说明（那就是把手选冒充成了识别结果）。

**记什么**：✓ 或 ✗ + 那句话的原话。

---

### 第 21 步 · 「再拍一张」能立刻重来

**要做什么**：在第 19/20 步那一屏，点「**再拍一张**」。

**成功的样子**：**立刻再拍一帧并重新识别一次**（不需要退回首页再点「拍照」）。连点两三次不卡死、不白屏。

**失败的样子**：没反应 / 退回了首页 / 白屏。

**记什么**：✓ 或 ✗。

---

### 第 22 步 · 识别失败 ≠ 帧被退回

**要做什么**：走完第 19 步之后，继续走到完成页，看「**被退回的帧**」这个数字。

**成功的样子**：这个数字**只统计"太暗/太糊"**的次数，**不包含**识物失败的那几次。

**失败的样子**：识物失败也被算进了"被退回的帧"。

**记什么**：✓ 或 ✗ + 你看到的数字，以及你实际拍了几次太暗/太糊。

---

### 第 23 步 · 弱网/服务端卡住时不会永久卡死

**要做什么**：制造一个"服务不可用"的情况，两种做法任选：

- **做法 A**：走到手机信号很差的角落（例如电梯口、楼道）
- **做法 B**（更简单）：**把电脑上的服务停掉**——切到第 2 步那个终端窗口，按 `Ctrl + C`，看到它停止

然后回到手机，点「拍照」→「快门」。

> ⚠️ 做完这一步记得**重新启动服务**（回到第 2 步的命令），否则后面的步骤做不了。

**成功的样子**：**最多等十几秒**（最坏约 24 秒），页面回到"**没能自动认出这个词**"那一屏，提示里会说"识物服务这次没能返回结果"。这一屏**仍有手选词包和「再拍一张」**。

**失败的样子**：**一直停在拍摄画面**（转圈、无反应、超过 30 秒还没结果）。

**记什么**：✓ 或 ✗ + 大约等了多久。

> 💡 **"等太久"必须是一条有出口的失败，不是卡死**——这是这一步要确认的核心。

---

### 第 24 步 · 等待期间连点快门不会堆积

**要做什么**：在第 23 步那种"等很久"的情形里，**连点几次「快门」**。

**成功的样子**：每次点击都各自走到一个结论（成功 / 手选屏 / 太暗太糊退回）。**不会**出现"点了没反应、越点越卡"。

**失败的样子**：点了没反应 / 越点越慢 / 最后白屏。

**记什么**：✓ 或 ✗ + 你点了几次、结果如何。

---

### 第 25 步 · 重拍次数数得对（这一步要去电脑上查记录）

**要做什么**：

1. 先在手机上走一次第 11 步（连续重拍 3 次，例如一直挡着镜头）
2. 然后到电脑上：打开 Chrome 或 Edge → 按 `F12` 打开开发者工具 → 顶部选「**Application**」（中文版可能是"应用"）→ 左侧找「**Local Storage**」→ 点开下面的网址 → 右边找到键名 **`elp.events`** → 点它

**成功的样子**：

- 每次按快门对应**恰好一条**记录（类型是 `frame_rejected` / `recognize_ok` / `recognize_failed` 三者之一）
- 每条记录里的 `roundIndex` 是 **1、2、3…** 逐次加一
- **一次快门里如果模型被问了两次**，你会看到 `payload.attempts` 是 2，但 `roundIndex` **只加 1**

**失败的样子**：`roundIndex` 跳号、重复、或每次快门对应两条记录。

**记什么**：✓ 或 ✗ + 你看到几条记录、`roundIndex` 分别是多少。

> 💡 这两个数字必须分开看：`roundIndex` 是"你按了几次快门"，`attempts` 是"这一帧问了几次模型"。

---

## 四、额度与安全（电脑上做，第 26–30 步）

### 第 26 步 · 被拒的帧不花额度

**要做什么**：

1. 在手机上对着纯黑/纯色画面拍，看到"太暗/太糊"提示
2. 切到电脑第 2 步那个终端窗口，看有没有新日志

**成功的样子**：**没有任何识物相关的日志行**（说明照片在手机本地就被拦下了，根本没发给模型）。

**失败的样子**：出现了 `recognize 失败` 或 `识物请求` 之类的行（说明前置拦截失效，额度被白花了）。

**记什么**：✓ 或 ✗ + 你看到的日志行（如果有）。

---

### 第 27 步 · 垃圾字节不花额度

**要做什么**：在电脑上**新开一个终端窗口**，输入下面这行并回车：

```
curl -k -i -F "image=@package.json;type=image/jpeg" https://10.68.199.114:8443/api/recognize
```

（`-k` 是"跳过证书校验"，因为证书是你自签的；把 IP 换成第 2 步打出来的那个）

**成功的样子**：返回 `400`，内容里有 `{"error":"bad_request"…}`，并且服务端（第 2 步那个窗口）**没有任何上游调用**（额度没被花掉）。

**失败的样子**：返回 `200`，或者服务端日志出现了上游调用。

**记什么**：✓ 或 ✗ + 返回的内容。

> 💡 这行命令的意思是"假装发一张 JPEG 图片，实际发的是文本文件"——检查服务端会不会被骗。

---

### 第 28 步 · 畸形的网址请求不会打死服务

**要做什么**：在终端里输入下面这行并回车：

```
curl -k -i "https://10.68.199.114:8443//"
```

然后**立刻再访问一次页面**（手机刷新，或电脑浏览器打开第 2 步那个地址都行）。

**成功的样子**：

- 命令返回 `400 Bad Request`
- 服务**仍在运行**，页面还能正常打开

**失败的样子**：命令没有回应 / 之后再访问页面打不开（说明服务进程被这一条请求打死了）。

**记什么**：✓ 或 ✗ + 返回的内容 + 服务是否还活着。

> 💡 这是一个**已经修好的严重缺陷**的回归检查：修复前，这一条请求就能让整个服务进程退出。

---

### 第 29 步 · 手选不污染识别成功率

**要做什么**：

1. 手机上走一次第 19–20 步（手选一个词）
2. 到电脑上按第 25 步的方法打开 `elp.events`
3. 找这一轮对应的记录

**成功的样子**：这一轮落的是 **`recognize_failed`**（带一个 `reason` 说明为什么没认出来），**不是** `recognize_ok`。

**失败的样子**：手选那轮也记了 `recognize_ok`（那样"识物成功率"就被手选污染了，数据不可信）。

**记什么**：✓ 或 ✗ + 你看到的记录类型。

---

### 第 30 步 · 隧道期间的额度消耗（重要）

**要做什么**：在服务开着隧道（第 3 步那个网址还有效）的时候，观察终端窗口有没有**不是你操作的**识物/反馈请求。

**成功的样子**：没有陌生请求。（注意：**不带图片的请求会直接返回 400、不会打上游**，所以单纯扫描打不穿额度。）

**要警惕的**：

- **带图片的请求会真的调用模型**，按次计费
- 所以**长时间挂着公网隧道是有风险的**

**记什么**：✓ 或 ✗ + 有没有看到陌生请求。

> ⚠️ **建议**：只在测试时开隧道，**做完就把第 3 步那个终端窗口关掉**（按 `Ctrl + C`），别让它挂着过夜。

---

## 五、造句反馈链路（第 31–38 步）

### 第 31 步 · 句子是否真的入库

**要做什么**：

1. 手机上走完第 16 步（写一句英文并提交）
2. 到电脑上按第 25 步的方法打开 `elp.events`
3. 在记录里**搜索你写的那句话**（开发者工具右侧有搜索框，或直接肉眼找）

**成功的样子**：能找到你写的那句原话，出现在某条记录的 `payload.sentence` 里。

**失败的样子**：翻遍记录找不到你的句子。

**记什么**：✓ 或 ✗ + 你找没找到、在哪种记录里找到的。

> 💡 目前（Task 9 之前）句子会进**反馈事件**的 `payload.sentence`，这已经够用了。

---

### 第 32 步 · 反馈真的回来了

**要做什么**：走第 16 步时，写一句 `I use a cup.`（目标词是 `mug`），提交后看反馈屏。

**成功的样子**：几秒内出现反馈屏，上面有：

- **你写的那句原句**
- 一条判定（"这句没问题" / "可以改得更地道" / "这句我拿不准"）
- 一条说明或改写建议

**失败的样子**：

- 一直转圈没有反馈（→ 见第 38 步）
- 反馈屏上没有你的原句

**记什么**：✓ 或 ✗ + 判定是什么、改写建议是什么。

---

### 第 33 步 · 拿不准时如实呈现、不伪装

**要做什么**：故意写一句**你自己也拿不准**的句子。推荐直接用**乱码**（这是最有效的触发方式），例如：

```
asdkjfh qweoru zxcvb
```

**成功的样子**：返回"**这句我拿不准**"，并且明确写着这**不算判定、不会算成通过**，同时**仍然给一条改写建议**。

**失败的样子**：

- 乱码被判成"这句没问题"（那就是在编造信心）
- 说了拿不准但**没有**改写建议

**记什么**：✓ 或 ✗ + 你写的那句 + 返回的判定原话。

> 💡 这一档是**设计上专门防止模型"不懂装懂"**的。它在开发时很难触发——实测只有**真乱码**能触发，写成"别扭但合乎文法"的英文（例如 `The mug it is on desk maybe.`）仍会被判成有问题。所以**请务必用乱码试**。

---

### 第 34 步 · 空句子提交不花钱、有提示

**要做什么**：在造句框里**什么都不写**（或只打几个空格），直接点「**提交造句**」。

**成功的样子**：**留在造句屏**，并提示"**先写一句你自己的话再提交**"之类，**不会**跳到反馈屏。

**失败的样子**：跳到反馈屏 / 转圈 / 没有任何提示。

**记什么**：✓ 或 ✗ + 提示原话。

---

### 第 35 步 · 失败时原句不丢、说清没拿到

**要做什么**：

1. 把电脑上的服务停掉（第 2 步那个终端窗口按 `Ctrl + C`）
2. 回到手机，写一句话并点「**提交造句**」

> ⚠️ 做完记得**重启服务**（回到第 2 步的命令）。

**成功的样子**：出现"**这次没拿到反馈**"+ 一句原因 + "**你的句子没有丢**"，并且**你写的那句话还显示在屏幕上**，还能再点「提交造句」重试。

**失败的样子**：你的句子消失了 / 显示了一个假的"没问题" / 一直转圈。

**记什么**：✓ 或 ✗ + 屏幕上的原话。

---

### 第 36 步 · 额度消耗看得见

**要做什么**：提交 2–3 句之后，看电脑第 2 步那个终端窗口的日志。

**成功的样子**：每次提交应有一行类似

```
feedback: word=… scene=… sentence="…"
```

**失败的样子**：没有这行日志（那样我就无法核对语料是否真的发出去了）。

**记什么**：✓ 或 ✗ + 把那一行抄下来（**句子内容可以照抄，那正是我要看的**）。

---

### 第 37 步 · 事件流里有句子、uncertain 单独一条

**要做什么**：提交几句（其中至少一句用乱码）后，到电脑上打开 `elp.events`。

**成功的样子**：

- 每次提交对应一条 `feedback_ok`（成功）或 `feedback_pending`（没拿到）
- 乱码那次应落**单独一条 `uncertain`**（**不是**混在 `feedback_ok` 里）
- 每条里都能看到你写的那句原话

**失败的样子**：`uncertain` 被记成了 `feedback_ok`（那样"拿不准"就被算成"通过"了）。

**记什么**：✓ 或 ✗ + 你看到哪几种记录类型。

---

### 第 38 步 · 等待期间不是死屏

**要做什么**：在第 35 步那种"服务停掉/弱网"的情形里，观察反馈屏。

**成功的样子**：有明确文案（"正在看你这句…"），并且「**再写一次**」「**下一个词**」两个按钮**都还在**（能点、有出口）。

**失败的样子**：白屏 / 只有一个转圈、没有任何按钮。

**记什么**：✓ 或 ✗ + 屏幕上有什么。

---

## 六、出问题时怎么办

| 现象 | 先试这个 |
|---|---|
| 手机打不开那个 `https://…:8443` 地址 | ① 确认电脑上第 2 步的窗口还在运行；② 确认手机和电脑连的是**同一个 Wi-Fi**（手机关掉流量试试）；③ 首次运行时 Windows 防火墙会弹窗问是否允许 node 联网，要选**允许** |
| 浏览器提示"证书不受信任" | 正常（自签证书）。按第 3.5 步装一次证书即可；不装也行，手点"继续访问" |
| 提示"连接不安全"且找不到继续入口 | iPhone 需要**两步**：装描述文件 + 在「关于本机 → 证书信任设置」里打开开关（漏了第二步就会一直提示） |
| 相机打不开，提示"安全上下文" | 你用的可能是 `http://` 而不是 `https://`。必须用 `https://…:8443` |
| 相机权限被拒了想改回来 | Chrome：地址栏左边图标 → 权限 → 摄像头 → 允许；Safari：设置 → Safari → 相机 |
| 看不到"识物相关日志" | 确认你看的是**运行服务那个窗口**（第 2 步的），不是下载证书那个 |
| 一切正常但想确认服务活着 | 电脑浏览器打开 `https://localhost:8443`，能出页面（有一次证书警告）就说明服务活着 |
| 想让手机也能用隧道（出门在外） | 本机环境三条隧道命令都不可用，原因见第 3 步的折叠段 |

**通用于所有问题**：**不要自己修**。记下编号 + 你看到的原话（截图也行），继续往下做。

## 八、已知的、不算问题的现象

看到下面这些**不用记成失败**，但可以注明"这是已知现象"：

- **第 9/10 步的判定阈值**（亮度 40 / 清晰度 80）是**首轮设定值，未经真实数据校准**。如果你觉得明显偏松或偏严（例如正常室内光也被判太暗），**如实记录当时的场景**——这正是首周校准要用的数据。
- **第 23 步最坏会等约 24 秒**，而且**等待期间没有"正在重试"的进度提示**，界面看起来是静止的。这是首轮设定值；若你觉得体感过长，记录当时的网络状况（这是调参依据）。
- **第 35/38 步反馈那条腿的上限**也是首轮设定值（客户端 24 秒 / 服务端 20 秒；实测正常网络下 1.3–2.6 秒返回）。同样**没有进度条**。
- **第 25 步的 `attempts` 可能大于 1**：同一帧最多问两次模型，这是有意的——**不做自动连拍，重拍由你决定**（这样"重拍率"才是真实数据）。
- **用词类型偶尔会被判成"语法"而不是"搭配"**：实测 `I very like my mug.` 被判成 `grammar`（而开发时预期是 `collocation`）。`very` 修饰动词确实是语法问题，**模型没判错**——这类分歧是后续分析要用的真实数据，不是缺陷。
- **第 33 步：别扭但合乎文法的英文可能触发不了"拿不准"**。实测只有**真乱码**能触发。如果你用别扭英文没看到"拿不准"，那是已知现象，不算失败；**但请把乱码那次的结果记下来**。
